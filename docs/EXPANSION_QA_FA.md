# گزارش تست و دروازهٔ انتشار وب

## نتیجهٔ تأییدشده
- موتور اجرا: `Godot 4.7.2.stable.official.ed1daf0bf`، لینوکس Headless.
- واردکردن تازهٔ پروژه بدون پوشهٔ `.godot`: کد خروج ۰ و **صفر ERROR**؛ حدود ۱۴ ثانیه در این محیط. این عدد بنچمارک دستگاه کاربر نیست.
- **۵۰ از ۵۰ اسکریپت تست موفق**؛ شامل ۴۷ تست موجود و ۳ تست جدید توسعه.
- اجرای نهایی از ابزار داخل بسته، `tools/run_tests.py`، استفاده کرده است. هر تست فرآیند و مسیر سیو مستقل داشت؛ اجراهای مستقل برای کاهش زمان به‌صورت موازی اجرا شدند.
- معیار قبولی: خروج ۰، وجود نشان PASS و نبود خطای اسکریپت/موتور یا FAIL. تستی که فقط PASS چاپ کند ولی بعد خطای موتور بدهد پذیرفته نمی‌شود.
- **۳۴ تست هشدار پاک‌سازی هنگام خروج دارند**، مانند `ObjectDB instances were leaked at exit` و/یا منابع استفاده‌شده هنگام خروج. ابزار آن‌ها را در `cleanup_warnings` جداگانه ثبت می‌کند. ادعای «بدون هشدار» یا «فاقد نشتی حافظه» نداریم؛ منشأ دقیق همهٔ این هشدارها حل نشده است.
- گزارش‌ها و لاگ خام کنار پوشهٔ `repo/` در `verification/` بسته قرار دارند و جزو فایل‌های لازم برای کامیت نیستند.

## پوشش تست‌های افزوده

### `test_expansion_characters.gd`
کاراکترهای تازه، آمار و سلاح شروع، پسیو اولیه، سقف ۵ ارتقا، سیو با شناسهٔ نامعتبر، ۷ کارت انتخاب، چیدمان یک‌ستونه در عرض کم و نبود کارت تکراری پس از بازشدن دوبارهٔ منو.

### `test_expansion_stages.gd`
قفل مراحل تازه، ترکیب موج، ساخت دشمن‌های تازه، سه حلقهٔ از پیش ساخته‌شده، هشدار پیش از آسیب، تفاوت ایستادن در خطر و جاخالی، شفای پناهگاه و جابه‌جایی آن، ثابت‌ماندن تعداد نودهای نشانگر.

### `test_expansion_budget.gd`
۳۰۰۰ درخواست اسپاون با سقف آزمایشی ۴۰: جمعیت فعال از ۴۰ بیشتر نشد و صف ثبت‌شده حداکثر ۳۲ بود؛ پذیرش درخواست نامعتبر، پاک‌شدن صف و منوی هفت‌مرحله‌ای نیز بررسی شدند. این تست معیار FPS مرورگر نیست و با سقف پیش‌فرض بازی فرق دارد.

## تغییرات موجه در تست‌های قدیمی
- انتظار ۹ پسیو به ۱۳ تغییر کرد تا محتوای افزوده‌شده را بشمارد.
- تست فشار به‌جای الزام ناسازگار ۲۴۰ دشمن، سقف واقعی تنظیمات PerformanceManager را بررسی می‌کند.
- نود اکتساب‌شدهٔ Pool در تست visibility قبل از خروج برگردانده می‌شود.
- چند انتظار و مسیر دسترسی تست‌های قبلی با UI و اصلاحات دیباگ موجود هماهنگ شد. تست‌ها برای پنهان‌کردن خطای runtime نادیده گرفته نشده‌اند؛ خطای متریال هنگام خروج واقعاً اصلاح شد.

## موارد اجرا نشده
**خروجی وب ساخته و در مرورگر اجرا نشده است.** بستهٔ کامل Export Templates این نسخه بیش از سقف ورودی محیط اجرا بود و دریافت جزئی آن از محیط ایزوله ممکن نشد. بنابراین موارد زیر تأیید نشده‌اند:
- بوت WASM، تعامل واقعی WebGL2، صوت و سیو مرورگر؛
- سرعت لود، زمان فریم، مصرف حافظه و پایداری در موبایل؛
- لمس، چرخش صفحه و میزان خوانایی رنگ‌ها روی نمایشگر واقعی؛
- پایان کامل دو مأموریت جدید در بازی واقعی و بالانس انسانی؛
- موفقیت workflow آنلاین یا استقرار GitHub Pages؛ هیچ اجرا/پوش آنلاین انجام نشده است.

## اجرای دوبارهٔ تست‌ها
از ریشهٔ پروژه در Linux یا WSL و با Godot 4.7.2:

```bash
godot --headless --editor --import --quit
python3 tools/run_tests.py --godot godot
```

برای یک تست:

```bash
python3 tools/run_tests.py --godot godot --test tests/test_expansion_stages.gd
```

گزارش در `build/test-results/summary.json` و لاگ‌ها کنار آن ذخیره می‌شوند. ابزار از `XDG_DATA_HOME` برای سیو موقت استفاده می‌کند؛ برای جلوگیری از لمس سیو شخصی، آزمون خودکار را در Linux/WSL یا حساب کاربری آزمایشی اجرا کنید. پیش از بازی آزمایشی از سیو اصلی بکاپ بگیرید.

## ساخت و تست دستی مرورگر — لازم پیش از انتشار
۱. Godot 4.7.2 و Export Templates دقیقاً همان نسخه را نصب کنید؛ پروژه را Import کنید و خطاهای Debugger را بررسی کنید.
۲. با preset موجود `Web` خروجی بگیرید. فولدر خروجی را خودتان بسازید:

```bash
mkdir -p build/web
godot --headless --export-release "Web" build/web/index.html
python3 -m http.server 8000 --directory build/web
```

۳. آدرس `http://localhost:8000` را باز کنید؛ فایل HTML را با `file://` اجرا نکنید. Console و Network را باز نگه دارید و خطاهای بارگذاری/Shader/Audio را ثبت کنید.
۴. حداقل Chrome/Edge دسکتاپ، Firefox دسکتاپ و Chrome اندروید روی یک گوشی میان‌رده را بررسی کنید. برای Safari/iOS نیز تست جدا لازم است؛ این بسته سازگاری آن را تضمین نمی‌کند.

| آزمون | معیار پذیرش پیشنهادی | نتیجهٔ این بسته |
|---|---|---|
| Cold boot و reload | بدون فایل 404، خطای WASM یا صفحهٔ سیاه | اجرا نشده |
| منوی انتخاب و کمپین | ۷ کارت، اسکرول کامل در ۳۹۰×۸۴۴ و دسکتاپ، ورود بدون انتخاب دوبارهٔ ناخواسته | تست واقعی اجرا نشده؛ چیدمان headless بررسی شده |
| هر دو کاراکتر تازه | سلاح، پسیو، رنگ و توضیح درست؛ سیو/بارگذاری انتخاب | مرورگر اجرا نشده |
| Storm | هشدار خوانا، امکان فرار، بدون ضربهٔ چندباره برای هم‌پوشانی؛ پیروزی بعد از ۲۴۰ ثانیه | منطق کوتاه headless تست شده؛ ران کامل مرورگر نشده |
| Grove | شفای درست و جابه‌جایی، پیروزی در ۲۵۰ kill | منطق کوتاه headless تست شده؛ ران کامل مرورگر نشده |
| فشار ۱۰ دقیقه‌ای | رشد نکردن مداوم صف، افت نکردن پیوستهٔ FPS، ثبت حافظهٔ قبل/بعد | اجرا نشده |
| سه چرخهٔ Restart/بازگشت به منو | نبود صدا/دشمن/نود باقی‌مانده و رشد غیرعادی حافظه | مرورگر اجرا نشده |
| Pause، فوکوس و صوت | توقف و بازگشت صحیح، صوت پس از تعامل کاربر | اجرا نشده |
| ذخیرهٔ پیشرفت | بسته‌شدن و بازشدن دوباره و حفظ unlockها؛ تست جدا برای Private Mode | اجرا نشده |

**هدف پیشنهادی، نه نتیجهٔ اندازه‌گیری‌شده:** دسکتاپ مناسب نزدیک ۶۰ FPS و موبایل میان‌رده حداقل ۳۰ FPS با تنظیمات پایین. دستگاه، مرورگر، رزولوشن، کیفیت و تعداد دشمن را همراه داده ثبت کنید. برای قضاوت از زمان فریم و روند حافظه استفاده کنید، نه صرفاً میانگین FPS. اگر هشدارهای خروج با رشد حافظه در Restart همراه‌اند، انتشار را متوقف و چرخهٔ مالکیت منابع را بررسی کنید.

## چه چیزی برای انتشار آماده است؟
کد و منابع تغییرکرده آمادهٔ بازبینی و کامیت روی شاخهٔ توسعه‌اند. تست‌های بومی موفق‌اند، اما تأیید نهایی کیفیت وب و بالانس هنوز کار باز است. ابتدا شاخه و Pull Request بسازید؛ پس از تکمیل چک‌لیست مرورگر به main ادغام کنید. workflow فعلی روی push به main یا workflow_dispatch اجرا می‌شود، نه صرفاً هر push به شاخهٔ توسعه.
