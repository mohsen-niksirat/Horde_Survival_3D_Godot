# Weapon balance — DPS table (V26A)

> Generated by `tools/balance_table.gd` from the `.tres` data.
> The model lives in `scripts/weapons/weapon_balance.gd` and is shared with
> the guard test `tests/test_v26a_balance_table.gd`, so the table and the
> game can never drift apart.
>
> ```
> godot --headless --path . --script tools/balance_table.gd
> ```

## Model — sustained single-target DPS

Derived from the real firing code (`scripts/weapons/weapon_controller.gd`):

| Type | Formula | Why |
|---|---|---|
| `projectile` | `damage x count / cooldown` | Every projectile of a volley lands on the target when it is alone — `_spawn_projectile` reuses the same target when there are not enough enemies. |
| `pierce` | `damage x count / cooldown` | Same as projectile; the pierce count is a crowd advantage, not a single-target one. |
| `aoe` | `damage / cooldown` | One strike per cooldown. The blast radius hits several enemies at once — a crowd advantage this number leaves out. |
| `orbit` | `damage x count / ORBIT_PERIOD` | The shields sweep at 2.0 rad/s, so one lap takes ~3.14 s and every shield can reach the same enemy. |

**Consequence:** only `projectile` and `pierce` weapons receive
`tier_projectile_bonus` from the tier curves. AoE and orbit weapons have to
compensate in their own `tier_damage_mult`.

## Changes in this pass (data files only)

1. **`data/weapons/lightning.tres`** — the AoE path fires a single strike, so
   Lightning never received `tier_projectile_bonus`. It grew 1.6x by tier 5
   while every other weapon grew ~4.8x, and it ended up the *weakest* weapon
   in the pool despite a fine tier-1 value.
   `tier_damage_mult = Array[float]([1.0, 1.4, 2.0, 3.0, 4.5])`
   → tier-5 DPS 14.9 → 46.7 (in line with Fireball's 48.0).

2. **`data/weapons/thunderstorm.tres`** — the evolution of Lightning must be a
   clear upgrade. With the old curve it was 56.0 DPS, only +20% over
   Lightning, while every other evolution grants +110% to +567%.
   `tier_damage_mult = Array[float]([1.0, 1.3, 1.8, 2.5, 3.6])`
   → tier-5 DPS 56.0 → 140.0 (+200% over Lightning).

3. **`data/weapons/orbiting_shield.tres`** — orbit weapons get the shield
   count bonus, but their single-target DPS is divided by the orbit period,
   so they grew 2.88x instead of ~4.8x and finished tier 5 far behind.
   `tier_damage_mult = Array[float]([1.0, 1.2, 1.5, 1.9, 2.4])`
   → tier-5 DPS 18.3 → 30.6, growth 4.80x.

## Guard test

`tests/test_v26a_balance_table.gd` locks the table in place:

- every weapon's damage is monotonic across the 5 tiers
- the 8 pickable pool weapons stay within a 2.5x tier-5 DPS spread
- every pool weapon grows at least 3.0x from tier 1 to tier 5
- no evolution is ever a downgrade over the weapon it evolves (min +50%)
- weapon data sanity: display name, positive damage, cooldown floor
  (exempt for orbit weapons, whose cooldown is a tick interval)

Re-run the table after any weapon data change:

```
godot --headless --path . --script tools/balance_table.gd
```

> **Note on the Godot resource format:** a typed `Array[float]` export must be
> written as `Array[float]([1.0, 2.0])` in a `.tres` file. Writing
> `PackedFloat32Array(1.0, 2.0)` is silently ignored — the property keeps its
> default value.
